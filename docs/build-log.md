# Build Log — Completed Units

What was built in each completed unit. See [CLAUDE.md](../CLAUDE.md) for the build sequence table and unit goals.

---

**Unit 0** — `docker-compose.yml` (Postgres 16 on 5433, Redis 7, API on 8001, Celery worker), `app/main.py` (`GET /health`, `POST /health/worker`), `app/tasks.py` (`ping` task).

**Unit 1** — `app/db/enums.py` (`BookStatus` + `LEGAL_TRANSITIONS` + `assert_legal_transition`), `app/db/models.py` (all 6 tables), `app/db/repos/` (one class per table), `migrations/versions/0002_schema.py`.

**Unit 2** — `app/providers/base.py` (`LLMProvider`, `ImageProvider` ABCs; `LLMResponse`, `CharacterRef`, `ImageResult` dataclasses), `app/providers/fake_llm.py` (`FakeLLMProvider` — injectable response queue, records calls), `app/providers/fake_image.py` (`FakeImageProvider`), `app/providers/factory.py` (`get_llm_provider` / `get_image_provider` driven by `Settings.llm_provider` / `Settings.image_provider`, both default to `"fake"`).

**Unit 3** — `app/agents/writer.py` (`WriterAgent.write(brief, method, prior_critique)` — 4 named methods, revision vs. fresh system prompts), `app/agents/judge.py` (`JudgeAgent.judge(story_versions, criteria)` — one LLM call per version, 3-retry loop with error fed back to LLM, `PROMPT_VERSION = "v1"`), `app/agents/base.py` (`JudgementResult`, `validate_judgement_json` — computes `passed` from threshold, not LLM opinion).

**Unit 5** — `app/events.py` (`publish_event` — sync Redis pub/sub; silently swallows errors so events never break the pipeline), `app/storage/local.py` (pre-existing gap: `LocalStorage` backing the dev storage seam), `app/api/__init__.py` + `app/api/books.py` (router: `POST /books`, `GET /books`, `GET /books/{id}`, `GET /books/{id}/versions`, `POST /books/{id}/approve`, `POST /books/{id}/reject`, `POST /books/{id}/retry`, `WS /books/{id}/stream`), `app/main.py` (mounts books router), `app/db/enums.py` (`AWAITING_APPROVAL` gains `REVISION` as a legal target for human rejection), `app/db/repos/book.py` (`list_all()`), `app/db/repos/story_version.py` (`list_for_book()`), `app/tasks.py` (all three pipeline tasks now call `_emit()` after each step, publishing a `status_change` event to Redis). Approve advances AWAITING_APPROVAL → APPROVED synchronously; reject sends AWAITING_APPROVAL → REVISION and re-enqueues `pipeline_handle_revision`; retry re-enqueues the right task for JUDGING or REVISION.

**Unit 6** — `app/providers/deepseek_llm.py` (`DeepSeekLLMProvider` — OpenAI-compatible client pointed at `https://api.deepseek.com`; streams via `client.chat.completions.stream()` + `.get_final_completion()`; routes writer calls to `deepseek-v4-pro` and judge calls to `deepseek-v4-flash` using `json_schema is not None` as discriminator; `max_tokens` 8192 writer / 1024 judge), `app/providers/factory.py` (adds `"deepseek"` branch with lazy import so fake-provider tests never require the SDK), `pyproject.toml` (`openai>=1.0` dependency), `.env.example` (`LLM_PROVIDER` + `DEEPSEEK_API_KEY` documented). Zero changes to agents or orchestrator. 145 tests, all passing offline.

**Unit 7 (partial)** — `app/providers/placeholder_image.py` (`PlaceholderImageProvider` — uses Pillow to generate labeled JPEG rectangles at exact 300 DPI spread dimensions from the book design spec; reads `params["spread_type"]` to select dimensions; renders prompt text and character_ref on a steel-blue-header / gray-body canvas; saves to `LocalStorage`; returns `ImageResult`). `app/providers/factory.py` gains `"placeholder"` branch with lazy import. `pyproject.toml` adds `pillow>=10.0`. `IMAGE_PROVIDER=placeholder` documented in `.env.example`. When Leonardo key arrives: add `LeonardoImageProvider`, set `IMAGE_PROVIDER=leonardo`, re-run `GENERATING_IMAGES` — no other code changes. 166 tests, all passing. Spread dimensions: `FULL_BLEED_DOUBLE` 5175×2625, single-page spreads 2625×2625, `PORTRAIT_WITH_CAPTION_BELOW` 2625×1838, `VIGNETTE` 1838×1838.

**Unit 4** — `app/orchestrator.py` (`Orchestrator` — sole owner of `BookRepo.transition()`; `start`, `run_judging`, `handle_revision` as the three pipeline phase methods; idempotent `_run_writing_round`; `_build_prior_critique` from best judgement of prior round), pipeline Celery tasks in `app/tasks.py` (`pipeline_start` → `pipeline_run_judging` → `pipeline_handle_revision` chain), `app/db/session.py` gains `get_task_session()` context manager.
